# 滑らかさの追加改善・第4回（2026-11-01）

前回PR #59の後の独立した次キューとして、移動開始の経路探索と歩行画像キャッシュを見直した。

## 修正

- 経路探索の待ち行列は先頭を削除せず、読み取り位置を進める。経路の復元も配列の先頭への挿入を繰り返さず、末尾へ追加して最後に1回反転する。探索方向の優先順、同距離の経路選択、通行制限は維持する。
- 移動開始前の確認で求めた経路を、そのまま移動処理へ渡す。同じ経路を確認と開始で2回探索していた処理を1回へ減らす。内部の省略可能な引数を補助処理まで引き継ぎ、従来の呼出しも保持する。無効な行先で現在の移動予定を失わないガードは維持する。
- 人物・敵・ペット画像の共用128件キャッシュは、最後に使った順で保持する。頻繁に使う歩行姿勢が、作成日時だけで捨てられて再生成される状況を防ぐ。キャッシュ上限と画像内容は変えない。

移動速度、遭遇率、戦闘計算、報酬、保存キー・形式は変更しない。経路やキャッシュは実行中の表示・移動処理で保持し、保存形式へ追加しない。

## 検証

- 旧探索方式を参照として、実MAPで1,344ケース（到達可能896ケース）の経路を完全比較。同距離の選択、遷移回避、移動不能、自分の位置を行先にしないことを確認する。
- 4サイズの実ブラウザー操作で、移動確認と開始を通した経路探索が1回で、サイズ変更後も経路を保って目的地へ到着することを確認する。最初の検査で中間の移動補助が経路を渡していない点を検出し、補助側も修正した。
- 150種類の別画像を生成する間も毎回使う歩行姿勢が同じ画像で保持され、使用しない古い画像が上限超過で解放されることを検査する。再生成画像の画素一致と上限128件も確認する。
- 既存の画面外描画・OS設定変更、停止再開・移動案内、メニュー描画などの検査も継続する。

ブラウザー模擬と検証用データによる確認。探索回数や画像再生成の抑制を実機のFPS改善率とは扱わない。物理スマホの体感・発熱は未確認。実利用者の保存データは使わない。

## ローカル結果

- 最終全回帰64/64、HTML構文、ビルド、生成物と配布候補照合が成功。
- 実MAPの1,344ケース（到達可能896ケース）の経路が旧方式と一致。
- 動作検査4サイズで、確認から移動開始までの探索1回、サイズ変更後の経路保持と到着、150種類の別画像追加中の歩行姿勢保持・画素一致・上限128件が成功。前回までのメニューと戦闘描画の検査も成功。
- 操作・案内検査4サイズで、実歩行、停止再開、手動解除、会話、戦闘選択、閲覧専用と古い押下の解除が成功。
