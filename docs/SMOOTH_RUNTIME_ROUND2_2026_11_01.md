# 滑らかさの追加改善・第2回（2026-11-01）

前回PR #57とは別の次キューとして、歩行のコマ間の時間処理とメニューの重複描画を調査した。

## 修正

- 歩行の1マスを終えた時、次のマスへ使えるフレーム内の端数時間を捨てていた。経過時間を次の区間へ繰り越し、30/60/90/120の描画回数で同じ時間なら同じ距離になるようにした。設定の1マス160ms・高速110msは維持する。
- 到着処理は通過した全マスで順番に行う。会話・メニュー・戦闘・MAPや状態の切替・経路差替え・ロック・タブ非表示・新しいループ世代へ移った時は、端数を次の区間へ流さない。従来の250ms上限で長い停止後の過剰な追いつきを防ぐ。
- 職業イベント/転職の切替は、検索語・対象の仲間を確定してから1回だけ描画する。いったん条件なしで描画してから検索語を戻して再描画する処理を解消した。
- メニューを開くクリック後の小画像描画は、画面描画内ですでに行うため、イベント末尾の重複呼出しを削除した。

セーブ形式・保存キー・戦闘計算・報酬・遭遇率は変更しない。到着回数を省略せず、入力解除や旧ループ無効化も維持する。

## 検証

`check-walk-cadence.mjs` で通常/高速×4種類の描画回数の距離一致、区間をまたぐ端数、到着順序、複数区間の到着、250ms上限、メニュー滞在中の時間を再生しないこと、戦闘など9種類の切替での停止を確認する。旧MAPループが別ループを作らない既存検査も実行する。

`test-smooth-runtime.mjs` に実際のメニューを開くタップの画面描画1回・小画像描画1回、および検索語・仲間を保った職業メニュー4回切替の各1回描画を追加した。前回のミニマップ画素一致、サイズ変更後の経路保持と到着、メニュー往復、敵画像再利用/撃破消去も継続する。

ブラウザーの画面サイズ・タッチ模擬と制御した検証用データで確認する。物理スマホの体感、実端末の高リフレッシュレート表示は未確認であり、単体検査の描画回数を実機測定とは扱わない。

## ローカル結果

- 追加の動作検査4サイズで成功。メニューを開く実タップは画面/小画像それぞれ1回描画、職業画面の切替は計16回すべて検索語・仲間を保持して各1回描画。
