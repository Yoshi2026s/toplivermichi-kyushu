# 回帰テストの出力先と再発防止

- 公開前に `npm run build:check` と `npm test` を実行する。Regression Actionsでも同じコマンドを実行する。
- 検証画像と検査結果はGit管理対象外の `.task/` に保存する。出力する各スクリプトが保存直前に親ディレクトリを再帰作成し、他のテストの実行順に依存させない。
- パスは `import.meta.url` またはスクリプトの配置場所を基準にする。呼び出し元の作業ディレクトリに依存させない。
- `check-clean-output.mjs` はHD画像・戦闘演出・海域画像の各検査を独立コピー上で実行する。各検査の前にコピー内の `.task/` がない状態へ戻し、リポジトリ外から起動してPNGの生成を確認する。
- 独立コピーにはOSの一時ディレクトリ内に作成した専用フォルダーを使用し、成功・失敗にかかわらず `finally` で削除する。開発者の作業用 `.task/` は削除しない。
- 通常の検査で生成した画像は確認用に保持する。新たな画像出力検査を追加した場合は、`check-clean-output.mjs` の対象にも追加する。

2026-10-30のENOENTは `.task/hd-art-contact.png` の親ディレクトリ未作成が原因。保存前のディレクトリ作成に加え、その処理を削除すると失敗する検査を維持する。

## CI環境差への対策

- 依存関係は `package-lock.json` をコミットし、Actionsとクリーン環境では `npm ci --ignore-scripts --no-audit --no-fund` でインストールする。公開候補にもロックファイルを同梱する。
- 全回帰テストはOSの一時ディレクトリを作業ディレクトリとして起動する。ファイルはリポジトリの絶対パスから読み、偶然の作業場所に依存するコードをCIで検出する。
- 公開ファイルを意図的に改変する `check-release.mjs` も、実行ごとに専用の一時コピーを作成し、`finally` で削除する。固定フォルダーの残骸や同時実行による干渉を防ぐ。
- 子プロセスの起動失敗・タイムアウト・シグナル終了は失敗として記録する。出力がない場合も残りの検査を継続し、検査結果JSONに原因を残す。
