# 滑らかさの追加改善・第3回（2026-11-01）

前回PR #58の後に依頼された独立した次キュー。今回は表示内容とゲーム進行を保ちながら、毎描画の画像取得・割り当て・設定問い合わせを削減する。

## 変更

- MAP上の画面外オブジェクトは画像取得とスプライト一覧への追加を省く。人物の揺れ、影、32×48のボスが画面端へ掛かる範囲を含む余白を設け、途中で絵を切らない。主人公・仲間・同行ペットは既存の処理を維持し、判定・経路・対象一覧からオブジェクトを除去しない。
- OSの演出抑制設定は1個の生きたMediaQueryListを再利用する。毎描画のmatchMedia呼出しを解消し、OSの変更はmatchesの変化で反映する。ゲーム内の抑制設定も優先する。
- 航海の静的なイベント目印は1枚のcanvasを再利用する。フレームごとに同じ16×24画像を作る処理を解消し、専用キャッシュは1件に制限する。

保存キー・保存形式、歩行時間、遭遇率、戦闘・報酬は変更しない。表示用キャッシュはセーブへ入れない。

## 検証

- 新しい単体検査は、4辺の余白境界、現在の絵と影の範囲、1000回の演出抑制確認でメディア問い合わせ1回、OS設定の変更、ゲーム設定による抑制、matchMedia非対応を検査する。
- 航海検査は既存の進行・保存・イベントに加え、100フレームで目印が同じcanvasかつ同じ画素で、専用キャッシュが1件であることを確認する。
- 新しいブラウザー検査は4サイズで、街・街外・全国編・航海の5MAP×3位置、計60場面を比較する。時刻・カメラ・canvas初期状態を揃えて、画面外省略の有無の画素を完全比較し、画像取得回数を記録する。2匹の同行ペットも含む。
- 最初の航海比較で2画素の差を検出したが、省略なしの連続描画でも同じ差を再現した。比較対象のcanvas初期状態を揃えることで解消し、画素の許容差は追加していない。
- 実ブラウザーでOS設定の変更を模擬し、キャッシュしたMediaQueryListが変化へ追従することを確認する。既存のOS設定単体テストも、生きたmatchesを表すgetterへモックを修正し、元の変更追従の検査を維持する。

物理スマホのFPS・体感・発熱は未確認。画像取得回数や時刻制御の検査を、実機のFPS測定とは扱わない。新規ブラウザーコンテキストと検証用データを使い、実利用者の保存データは触らない。
